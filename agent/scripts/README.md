# Скрипты — единственный способ действовать

Персонаж наблюдает и действует через них и больше никак. Он не запускает инфраструктуру, которая запускает его.

Контракт нарочно скучный: скрипт принимает простые аргументы и печатает простой результат. Поэтому его можно вызвать из любого раннера, проверить руками и прочитать в логе.

| скрипт | что делает |
| --- | --- |
| `entries.sh` | записи дневника: по теме, за период или с даты |
| `topics.sh` | сколько записей по каждой теме за период |
| `link.sh` | сколько раз две темы встречались в одной записи |
| `say.sh` | дописать сообщение в исходящие, адресованное человеку |
| `remember.sh` | дописать датированную строку в заметку, заведя её при необходимости |
| `ticket.sh` | сообщить, что чего-то не хватает или что-то сломано |
| `sleep.sh` | назначить себе следующее пробуждение, в минутах |

Первые три ходят в дневник через `_diary.py`. Пока адаптер не настроен, они честно печатают, чего не хватает, и выходят с ненулевым кодом. Это не заглушка ради вида: персонаж должен уметь отличить «данных нет» от «инструмент не работает».

Важно про границу. `entries.sh`, `topics.sh` и `link.sh` дают возможность, а не сценарий. Что спросить у дневника и стоит ли вообще отвечать, решает персонаж.
